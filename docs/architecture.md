# Architecture

`oathshaper-core` is pure Rust. It parses a strict JSON graph, validates references and variable names, evaluates conditions, commits effects atomically, creates display views, and serializes versioned saves. Given the same story and session commands, it produces the same state. It has no Godot dependency. `Story` and `NarrativeSession` can be used by a CLI, editor, or server without a scene tree.

Response nodes declare `return_to`, a validated question-menu ID. The core's `finish_response()` changes only the current node; Godot decides when to invoke it from voice length, estimated reading time, or B/Esc. This keeps wall-clock timing out of deterministic narrative rules. The panel pauses its presentation clock with the ledger and cancels it on exit/load. NPC sway uses independent Godot presentation RNGs and never changes narrative state.

`oathshaper-godot` is a thin GDExtension adapter. Its `NarrativeBridge` methods return JSON envelopes (`ok` plus `data` or `error`) for story validation, session actions, and save/load. `begin_at(node_id)` opens any authored conversation entry and rejects an unknown ID without changing the session. `state_json()` exposes the current Rust state for presentation. `choose_with_events` exposes the core's `ChoiceOutcome`: the new view and a `choice_committed` event emitted only after a successful transaction. The demo uses the simpler `choose` view method. Future combat can consume committed events and map stable choice IDs to encounter commands; no combat rules or commands are implemented yet.

Godot owns the 3D scene, player and camera, character presentation, NPC proximity, input actions, subtitles, button focus, optional voice playback, lamp presentation, and a world-save envelope containing the Rust save plus player position. The scene maps the four NPCs and records cabinet to stable dialogue entry IDs; it never infers rules from mesh or scene names. After a choice or load, it reads `state_json()` and applies `oil_shared` to Mara's lamp, `gate_open` to the east tide gate, and `shortcut_open` to the market–court passage. Revision 3 adds `records_clue` and `records_collected`: these drive the objective stage, map waypoint, cabinet bundle, and Inventory display. `hub_environment.gd` generates the bounded district, collision, landmark, two removable barriers, and signed west archive door. `records_office.gd` generates the separate roofless office and filing cabinet. `map_widget.gd`, `objective_tracker.gd`, and `journal_menu.gd` present location and story state; the journal asks the scene to save or load. Godot does not decide whether an authored choice qualifies.

The content file is ordinary versioned JSON at `godot/content/lantern_quay.json`; dynamic dialogue generators can submit graphs through the same `load_story_json` validation boundary. There is no dynamic generator yet. The tower loads a supplied textured GLB at `res://assets/meshes/lantern_tower.glb`, with primitive art as its fallback; its footprint collider and beacon light remain scene-owned. `character_model_slot.gd` loads supplied player, Mara, Ivo, clerk, and vendor GLBs and hides matching primitive visuals only when an imported scene contains visible mesh geometry. All five characters use skinned derivatives with animation clips. The slot can fall back to static art or primitives. It does not retarget or blend skeletal clips or drive root motion. The [rigging guide](rigging.md) gives the clip and fallback contract. Scene-owned collision, proximity, labels, and dialogue remain in place. The [character concept PNGs](../art/concepts/README.md) are modeling references, and the [four-view dock package](../art/meshy/dock/README.md) captures existing geometry for Meshy; neither is an imported runtime mesh. The archive door, office, furniture, records, map, and journal are original procedural Godot assets and code. The exact prompts, inputs, licenses, and redistribution rights for the [supplied GLBs](../godot/assets/meshes/README.md) are unverified; the MIT code license does not grant asset rights.

The content and save schemas each carry a version. Saves also carry story ID and revision, and the core rejects incompatible or malformed state before replacing the live session. The hub story is revision 4 and `demo.gd` writes `user://oathshaper_hub_v4.save.json`; older narrative revisions are not migrated. A later milestone will add explicit migrations and authorable event types. The [hub validation record](hub-expansion.md#validation-boundary) distinguishes earlier checks from verification of the records route and new UI.
